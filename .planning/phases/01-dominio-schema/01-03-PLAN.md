Define `func RunScheduleMigrations(db *sql.DB) error` following the rules-service pattern (single multi-statement string executed with db.Exec).

The migration SQL must contain these statements in order:

Statement 1 — Create schedules table:
```sql
CREATE TABLE IF NOT EXISTS schedules (
    id              VARCHAR(36) PRIMARY KEY,
    owner_id        VARCHAR(255) NOT NULL,
    name            VARCHAR(255) NOT NULL,
    description     TEXT NOT NULL DEFAULT '',
    schedule_type   VARCHAR(20) NOT NULL,
    cron_expr       VARCHAR(100) NOT NULL DEFAULT '',
    run_at          TIMESTAMP,
    days_filter     INTEGER NOT NULL DEFAULT 0,
    timezone        VARCHAR(64) NOT NULL DEFAULT 'UTC',
    action_target   VARCHAR(10) NOT NULL,
    action_type     VARCHAR(50) NOT NULL,
    action_device_id VARCHAR(255) NOT NULL DEFAULT '',
    action_payload  TEXT NOT NULL DEFAULT '',
    enabled         BOOLEAN NOT NULL DEFAULT true,
    created_at      TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMP NOT NULL DEFAULT NOW(),
    last_run_at     TIMESTAMP,
    next_run_at     TIMESTAMP
)
```

Statement 2 — Create owner_id index:
```sql
CREATE INDEX IF NOT EXISTS idx_schedules_owner_id ON schedules(owner_id)
```

Statement 3 — Create enabled index:
```sql
CREATE INDEX IF NOT EXISTS idx_schedules_enabled ON schedules(enabled)
```

Statement 4 — Create schedule_executions table:
```sql
CREATE TABLE IF NOT EXISTS schedule_executions (
    id            VARCHAR(36) PRIMARY KEY,
    schedule_id   VARCHAR(36) NOT NULL REFERENCES schedules(id) ON DELETE CASCADE,
    executed_at   TIMESTAMP NOT NULL DEFAULT NOW(),
    status        VARCHAR(20) NOT NULL,
    error_message TEXT NOT NULL DEFAULT ''
)
```

Statement 5 — Create executions index:
```sql
CREATE INDEX IF NOT EXISTS idx_executions_schedule_id ON schedule_executions(schedule_id)
```

Use the rules-service approach: concatenate all statements in a single backtick string separated by semicolons, execute with single `db.Exec(migration)` call. On error, return `fmt.Errorf("failed to run schedule migrations: %w", err)`. On success, `log.Println("Schedule service migrations completed successfully")`.

Column details rationale:
- `run_at TIMESTAMP` nullable: only set for one_shot schedules (SCH-07)
- `days_filter INTEGER NOT NULL DEFAULT 0`: bitmask, 0 = all days (SCH-06)
- `timezone VARCHAR(64) NOT NULL DEFAULT 'UTC'`: IANA timezone (SCH-09), always present even if UTC-only in v1
- `last_run_at TIMESTAMP` nullable: set after first execution
- `next_run_at TIMESTAMP` nullable: computed by scheduler
- `schedule_type VARCHAR(20) NOT NULL`: "cron" or "one_shot" (SCH-05, SCH-07, SCH-08)
- `ON DELETE CASCADE` on schedule_executions: deleting a schedule removes its history
